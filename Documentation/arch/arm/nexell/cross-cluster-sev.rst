S5P6818 cross-cluster CPU events
================================

The S5P6818 contains two Cortex-A53 clusters.  A CPU event generated by
``SEV`` is not delivered to a waiter in the other cluster.  This matters for
the ARM ticket, read/write, and MCS lock wait paths, which traditionally use
``WFE`` after observing a contended lock.

The ``CONFIG_NEXELL_S5P6818_NO_CROSS_CLUSTER_SEV`` option enables the scoped
workaround.  The ARM lock wait code retains the normal ``WFE`` implementation
until the S5P6818 machine description is selected during device-tree boot.
Only then does it poll contended lock state with ``cpu_relax()``.  A kernel
that also contains other ARM multi-platform support therefore keeps ``WFE``
when booted on a non-S5P6818 machine.

Unlock-side ordering and ``SEV`` are unchanged.  The workaround increases
power and interconnect traffic while locks are contended, so it must not be
enabled as a generic ARM policy or copied to SoCs without the same event
delivery limitation.

This is a hardware-specific workaround, not evidence that the S5P6818
EVENTO-to-EVENTI path can be enabled by a Linux register write.  The vendor
secure-firmware implementation uses an explicit software relay for the
supported CPU-power lock path.
